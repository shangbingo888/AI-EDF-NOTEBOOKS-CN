# Notebook 主题与提示框约定

这篇记录本仓库在**渲染层面**的约定：一个 `.ipynb` 交到 Colab 和 GitHub 手里之后，
哪些样式手段能用、哪些不能用，以及替代方案是什么。

## 硬性限制

一个 `.ipynb` 由 **Colab** 和 **GitHub** 渲染，而这两者各自掌控自己的 CSS：它们会从
markdown cell 里剥掉 `<style>` 块和 `class` 属性。所以**任何外部样式表都进不来**，
除非把 notebook 转成 HTML、由你自己托管（见「导出成 HTML」）。

真正能跨各种查看器通用的，是**内容结构**和**提示框**。

## 提示框：用 emoji 标注的引用块（不用 `[!ALERT]` 语法）

一个吃了亏才学到的坑：**GitHub 的 notebook（`.ipynb`）渲染器不是它的 markdown 文件
渲染器。** `[!NOTE]`/`[!WARNING]` alert 扩展在 `.md` 文件、issue 和 README 里有用，但
**在渲染出来的 notebook 里没用**，在 Colab 里也没用。在两种 notebook 查看器里，
`[!NOTE]` 都只是普通引用块里的一段字面文字。所以我们**不用**它。

改用：一个由 **emoji + 加粗标签** 打头的普通引用块。干净，在 Colab 和 GitHub 里长得
一模一样；即便没有颜色，emoji 也扛起了角色。

```markdown
> **⚠️ Production reality —** the usage chunk arrives last; drop it and you lose the bill.
```

角色 → emoji → 含义：

| 角色 | Emoji | 用在 |
|---|---|---|
| 核心要点 | ⭐ | 唯一要记住的那件事 |
| 原因 | 💡 | 好理由 / 正面 |
| 面试信号 | 🔵 | 面试环节会奖励的信息 |
| 生产现实 | ⚠️ | 生产里会咬人的东西 |
| 常见错误 | 🚩 | 反模式 / 危险 |

规则：
- 提示框要**稀少**，每个 notebook 1–3 个。如果每段都被框起来，就失去力度了。
- 永远写成 `> **<emoji> <Label> —** <text>`。
- 不要挪用某个角色的 emoji/含义。

**想在原始 notebook 里得到真正的彩色框，唯一的办法**是用内联 HTML 加内联 `style=`
（一个 `<div style="border-left:4px solid #d1242f;…">`）。它在两种查看器里都渲染，但会把
原生 HTML 塞进 cell。我们选择*不*这么做，宁可保持源码干净；等彩色框真的值回代价时再议。

## 图表：用代码围栏的制表符画法，不用 Mermaid

跟 `[!NOTE]` 一样的坑，一样的原因。**Mermaid 在两个目标查看器里都不渲染：** GitHub 的
`.ipynb` 渲染器不是它的 markdown 文件渲染器（Mermaid 在 `.md`/issue/PR 里能用，*在
渲染出的 notebook 里不能*），而 Colab 从来就没在 markdown cell 里渲染过 Mermaid。一个
```` ```mermaid ```` 块在**两者里都显示为原始源码**，比纯文本还糟。所以我们不用它。

在 *Colab 和 GitHub 两者里*都能静态渲染成真图表的：

- ✅ **围栏块里的 ASCII / Unicode 制表符画法**——默认选择。零依赖、可当文本编辑、
  diff 干净。制表符字形（`┌ │ └ ─ ▶ ·`）没问题；它们在两种查看器给代码围栏用的等宽
  字体里都渲染为宽度 1（这是本仓库既有的惯例）。
- ✅ **一张提交进仓库的图片**（`![](…/foo.svg)`）或一个 **`mermaid.ink` 图片 URL**——
  可移植，但会多出一个资产/外部依赖，而且不能再就地编辑。只有当制表符画法确实表达
  不出那个形状时，才用它。

制表符画法的规则：
- **对齐到固定的内部宽度。** 把每一行内部内容补到同样宽度，让左右两壁和四个角都落在
  同一列上。用一个小脚本生成，别靠肉眼估；看看 `05/06-harness-engineering` 是怎么搭
  的。确认*每一*行（含四角）的左右边框列都对齐。
- **在需要对齐的地方避开宽度有歧义的字形**：带圈数字（`①②③`）和许多 emoji 可能渲染
  成 2 宽，悄悄把网格撑破。宁可用 `(1) (2) (3)`。制表符和箭头字形是安全的。
- 如果某个图表偏偏在 Colab 里看起来错位，退回**纯 ASCII** 版本（`+---+`、`-->`、
  `[1]`）：零歧义宽度字形。

## 内容结构：统一的推进方式

每篇 notebook 用同一套推进方式，让读者始终清楚自己身在何处：

1. **它是什么**——概念和具体场景，放在任何代码之前。
2. **它怎么运作**——机制 / 那把「梯子」或流水线，常常配一张一眼能看懂的表格。
3. **细节**——深度：每个阶段、它的失败模式，都现场演示。
4. **实践与反模式**——✅/❌ 回顾表（见最佳实践文档）。
5. **练习题**——做完再往下走。

## 导出成 HTML（想要彩色提示框时的唯一办法）

emoji 提示框在任何查看器里都不会坏，但它没有颜色。想要真正带色的框，就把 notebook
导出成 HTML 自己托管：

1. `jupyter nbconvert --to html --template lab <nb>.ipynb`
2. 在导出的 HTML 里注入你自己的样式表，给引用块加上左边框配色。
3. 保持 Colab 徽章指向 `.ipynb`，供可运行的那份使用。

眼下以 markdown 为主；等某篇 notebook 该变成独立页面时，再回头做这件事。
